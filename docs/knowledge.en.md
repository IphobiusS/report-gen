# Library, field guidance and work packages

The library provides **90 entries**, each authored in ES/EN/PT: 18 web, 12 API, 8 identity/AD, 8 infrastructure, 8 cloud, 6 mobile and 30 AI patterns. Text is intended for adaptation to evidence and scope; it is not a result obtained against a customer.

## Read and use an entry

1. Open **Finding library** and choose **Curated catalog**. **My library** continues to contain your private templates.
2. Search names, IDs, text or tags, or filter by category. Changing the catalog language neither translates nor modifies your report.
3. Open details. Review prerequisites, required evidence and false positives before deciding whether the pattern applies.
4. Copy it to My library or add it to the project with a concrete target. Insertion saves the project first and checks its revision. A conflict during that save can be resolved before retrying the same form. If the insertion response does not confirm its outcome, reload and inspect the project before discarding the pending form and starting another insertion; this avoids duplicates.
5. The draft remains **unverified**, with severity/CVSS pending. Adapt the text, record observations and assess impact before reaching a conclusion. Proposed evidence never becomes collected evidence automatically.

Personal copies retain conditions, notes and retest in editable fields. The bundled catalog is read-only. Future catalog editions do not rewrite personal copies or existing project findings. The library works offline; opening external references requires a connection.

## Work packages

From the library, open **Work packages**. Select a specialty, review the scope prompts and enter a title and client. Pending test cases are created for the entries in that specialty. Suggested findings are optional: select only the drafts you want to prepare.

**Create independent project** saves the open project before switching. A save failure stops the operation. The new project uses an editable corporate structure and does not alter the previous project. Missing targets remain visible as `{{objetivo}}`, pending completion. Selecting a package does not establish executed methodology or comprehensive coverage.

## Guidance and annotated example

Writing fields offer optional guidance with an adequate and an insufficient example. Reading guidance changes no values or approvals. **Annotated report** provides nine notes about provenance, executive summary, scope, evidence, impact, severity, remediation, retest and delivery in Nimbus.

Create an independent Nimbus practice copy to read and export the complete report. Its data and results are fictional. Teaching notes remain in the interface and are not added to customer exports. Practice retains access to the previous project.

## AI content and maintenance

The 30 entries cover instruction injection, information exposure, RAG, memory, tools, agent identity and communication, approval, model supply chains, tuning data and resource consumption. They require observable impact, conditions and comparison tests; an isolated jailbreak does not establish an impactful vulnerability.

The editorial review date is **October 17, 2026**. Entries cite OWASP LLM Top 10 2026, Agentic Applications 2026 and NIST AI 100-2e2025 where applicable. The previous OWASP 2025 selector retains its IDs and edition. This library is not an exhaustive CVE inventory and receives no silent remote updates. Check each reference's version and date before a new assessment.

Automated acceptance is described in [QA-KNOWLEDGE-0440.md](QA-KNOWLEDGE-0440.md). Junior/senior comprehension requires participant sessions; tests cannot establish it.
