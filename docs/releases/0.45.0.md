## Español

**0.45.0 consolida la estabilidad de report-gen con una auditoría transversal del editor, los exportadores, los datos, las integraciones y el mantenimiento.** Las correcciones preservan las evidencias y decisiones del analista, añaden regresiones para los defectos reproducidos y retiran únicamente código cuya redundancia o inaccesibilidad se ha demostrado.

### Qué cambia

- **Exportaciones y portadas:** las salidas auxiliares PDF/HTML se preparan antes de publicarse y recuperan los archivos anteriores si falla un reemplazo ordinario. Se rechazan destinos coincidentes. Se conservan los contactos vacíos y sus enlaces, el cargo de un evaluador sin nombre y los valores numéricos cero admitidos en la portada.
- **Cancelación y limpieza:** la cola respeta cancelaciones durante la limpieza final, conserva el seguimiento de temporales privados cuyo borrado falla y reintenta su eliminación. El listado de trabajos evita purgas anidadas durante su serialización.
- **Importaciones e integridad:** Burp y ZAP conservan Unicode y URLs sin escapes añadidos; se endurece la validación de métricas CVSS 3.1 y estados HTTP en HAR. Los anexos reconocen nombres Unicode equivalentes y los límites UTF-8 no dividen caracteres.
- **Evidencia HTTP:** cambiar el archivo HAR o la selección de una comparación descarta respuestas tardías. La importación conserva una selección coherente. Las regresiones incluyen DOM y navegador real en ES/EN/PT.
- **Retest y privacidad:** un retest histórico no sustituye una observación posterior. Las comparaciones compartibles excluyen etiquetas privadas del historial y la evidencia de instancias y sus retests se reconoce como asociada. Las entradas malformadas se rechazan de forma controlada y los intercambios conservan copias independientes.
- **Publicación:** las sustituciones literales también alcanzan el texto editable del certificado en la portada. Los originales y las opciones estructurales permanecen intactos; una sustitución que invalida el diseño bloquea la salida.
- **Asistente de terminal:** los identificadores siguen la secuencia del documento, las imágenes reciben nombres disponibles y la creación rechaza proyectos existentes. Cerrar la entrada termina de forma controlada, sin sobrescribir evidencias por coincidencias de nombre.
- **Limpieza y aceptación:** se contrastan referencias estáticas, rutas Flask, plantillas y carga dinámica. Se conservan callbacks e interfaces públicas documentadas. Continúa la aceptación de cuatro formatos, tres idiomas, informes complejos, plataformas, navegadores y renderizadores nativos, junto al paquete fuente reproducible.

Consulta el [registro de cambios](../../CHANGELOG.md#cambios-0450-2026-10-17) y el [alcance de la auditoría](../QA-AUDIT-0450.md) para el detalle técnico.

### Descargar e instalar

Descarga el [ZIP de fuentes de 0.45.0](https://github.com/IphobiusS/report-gen/releases/download/v0.45.0/report-gen-0.45.0-9693c808ee35.zip), su [SHA-256](https://github.com/IphobiusS/report-gen/releases/download/v0.45.0/report-gen-0.45.0-9693c808ee35.sha256) y el [manifiesto JSON](https://github.com/IphobiusS/report-gen/releases/download/v0.45.0/report-gen-0.45.0-9693c808ee35.json). El SHA-256 permite comprobar el ZIP y el manifiesto identifica cada archivo del árbol publicado.

Requiere **Python 3.11 o posterior** y conexión para instalar dependencias. En Linux/Kali, descomprime el ZIP, entra en la carpeta extraída y ejecuta:

```bash
python3 scripts/install.py --desktop
~/.local/bin/report-gen
```

Abre **http://127.0.0.1:8080**. El instalador no utiliza `sudo` ni instala paquetes del sistema. Conserva la carpeta de la aplicación y su `.venv`: el acceso depende de ambas; el ZIP no es un ejecutable autónomo. Node.js no es necesario para usar el editor.

Para actualizar, detén el editor y utiliza una carpeta nueva, conservando tu espacio de trabajo externo. Revisa la [guía de instalación y actualización](../guide.es.md) antes de trasladar datos o retirar una instalación anterior.

## English

**0.45.0 strengthens report-gen's stability through an audit of the editor, exporters, data handling, integrations and maintenance.** Fixes preserve analyst evidence and decisions, add regression checks for reproduced defects and remove code only where redundancy or unreachability has been demonstrated.

### What changed

- **Exports and covers:** companion PDF/HTML outputs are prepared before publication and previous files are restored if an ordinary replacement fails. Identical destinations are rejected. Empty contact sections and their links, an assessor's role without a name, and permitted numeric zero values in cover metadata are retained.
- **Cancellation and cleanup:** the queue respects cancellation during final cleanup, retains tracking for private temporary files that could not be removed and retries removal. Job listings avoid nested purges while serializing records.
- **Imports and integrity:** Burp and ZAP retain Unicode and URLs without added escapes; CVSS 3.1 metrics and HAR HTTP statuses receive stricter validation. Attachments recognize equivalent Unicode filenames and UTF-8 limits do not split characters.
- **HTTP evidence:** changing a HAR file or comparison selection discards stale responses. Imports retain a consistent selection. Regressions cover the DOM and real browsers in ES/EN/PT.
- **Retesting and privacy:** historical retests do not override later observations. Shareable comparisons exclude private history labels, and evidence attached to instances and their retests is recognized as associated. Malformed input receives controlled rejection and exchanges retain independent copies.
- **Publication:** literal replacements also cover editable certificate text on the cover. Originals and structural options remain intact; a replacement that invalidates the design blocks output.
- **Terminal wizard:** identifiers follow the document sequence, images receive available filenames and project creation rejects existing destinations. Closing input terminates gracefully without overwriting evidence because of filename collisions.
- **Cleanup and acceptance:** static references are checked against Flask routes, templates and dynamic loading. Documented callbacks and public interfaces remain available. Acceptance continues across four formats, three languages, complex reports, platforms, browsers and native renderers, alongside the reproducible source package.

See the [changelog](../../CHANGELOG.md#cambios-0450-2026-10-17) and [audit scope](../QA-AUDIT-0450.md) for technical details; both source documents are in Spanish.

### Download and install

Download the [0.45.0 source ZIP](https://github.com/IphobiusS/report-gen/releases/download/v0.45.0/report-gen-0.45.0-9693c808ee35.zip), its [SHA-256 file](https://github.com/IphobiusS/report-gen/releases/download/v0.45.0/report-gen-0.45.0-9693c808ee35.sha256) and the [JSON manifest](https://github.com/IphobiusS/report-gen/releases/download/v0.45.0/report-gen-0.45.0-9693c808ee35.json). The SHA-256 checks the ZIP; the manifest identifies every file in the published tree.

Requires **Python 3.11 or newer** and a connection to install dependencies. On Linux/Kali, extract the ZIP, enter the extracted directory and run:

```bash
python3 scripts/install.py --desktop --lang en
~/.local/bin/report-gen
```

Open **http://127.0.0.1:8080**. The installer does not use `sudo` or install system packages. Keep the application directory and its `.venv`: the shortcut depends on both; the ZIP is not a standalone executable. Node.js is not required to use the editor.

To upgrade, stop the editor and use a new application directory while retaining your external workspace. Read the [installation and upgrade guide](../guide.en.md) before transferring data or retiring an earlier installation.

### Validation and limitations

All [seven publication checks](#validation) completed successfully for the stated commit. The links identify those specific runs, not later results on `main`.

Automated checks do not guarantee universal freedom from bugs or dead code and do not replace visual report review. File recovery is not an indivisible transaction against power loss. Windows compatibility and LibreOffice rendering **do not certify desktop Microsoft Word**. Human junior/senior sessions and real Burp, Jira, DefectDojo and Ollama acceptance require separate records.
